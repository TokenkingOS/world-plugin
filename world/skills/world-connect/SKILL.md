name: world-connect
description: 接入 world、核对当前身份及能力，或在连接后查询本人工作时使用。

让成员用既有本人账号连接 world，核对当前公司与职责，再查询本人有权读取的工作。

## 接入与核对

插件使用独立应用连接 `https://world.tokenkingos.com/app/mcp` 和宿主原生 OAuth 登录。本人在宿主打开的登录页填写邮箱、密码并选择公司；首次设密码按登录页的邀请码流程办理。登录材料由本人和宿主处理，不经过对话正文。

连接后调用 `world_get_connection`，向本人说明返回的主体、公司范围、访问级别与当前角色。范围不对时由本人重新选择公司；401/403 或连接失败时说明实际错误，保留尚未核对的状态。返回 `SERVICE_BUSY`（503，服务忙，什么都没提交，带 `retry_after_seconds`）时，不要说成连不上或没有权限：等够这些秒后原样重试，最多三轮，仍忙就如实告诉本人服务忙。写入的恢复办法见各写入技能。`EVIDENCE_UNAVAILABLE`（证据存储或数据库不可用）不是忙，没有等多久的说法，如实说明，不连续重试。

当前对话里看不到 `world_get_connection` 等 world 工具时，先不下结论。刚登录或刚连接的，宿主可能还没把工具交给这一轮：请本人再问一次；仍看不到，就新开一个对话或重启宿主再核对。新对话里仍然没有，才说明这个连接缺哪些工具，并请本人把宿主里 world 连接下列出的工具发给维护方。不要说成服务端缺工具，不将握手成功当作已完成身份与能力核对，也不要求成员安装 Python 或执行业务命令补救。

按返回分别说明查询、记录、本人操作、工作来源和自动采集能力。`unknown` 表示尚无覆盖证据，不能解释为没有工作变化。`requires_authorization` 表示具体写入还须核验来源、目标与当前权限。`partial` 要列明实际已接通的范围；本人操作尚未接通时明确说明。老的 `/mcp` 和本机 MCP 在 2026-11-20 18:00（UTC+8）下线，不以其工具替代应用的确认。连接和安装本身不启用本机采集。

## 查询本人工作

用 `world_list_objects` 找相关 Mission/Task，取全分页，再用 `world_get_object` 核对每项 `identity.responsible.principals` 是否包含当前主体。Mission 或责任单元的 DRI 不自动成为 Task DRI；没有匹配项时如实说明，不将别人的任务列为本人的。

回答注明对象的 `business.version`、生命周期、来源和事实截至时间。状态快照的 `as_of` 是观察时点，运行或连接成功时间不刷新业务事实。确认态、草稿、未经确认状态和缺口分别表达。

需要进一步回答业务问题时使用所连接工具的说明与现行 world 规则。接入检查不产生业务记录，也不批准后续写入。

本人问“有哪些待办／待我确认”时，合并 `world_pending_gates`、`world_app_list_work_items` 与 `world_app_sources_service_candidates` 的全部分页。按原工作项或源事件去重，区分现在可办、等谁及来源/授权已变化的事项。服务来源中已明确的普通事实不再次询问；指派、完成等提议在有权本人愿意办理时用 `world_app_sources_prepare_service_candidate` 展示当前准确差异，再沿本人工作项确认、提交和独立读回。查询清单不构成批准。工具未接通或来源尚未归位时说明覆盖缺口，不把清单为空说成全部没有待办。

常规升级使用 Agent 宿主的插件更新入口；本机来源组件使用其产品更新入口。保留本人登录、来源选择和原工作项，升级后重新核对连接与原结果。显示“未接通签名更新”时交维护方配置发布，成员不运行安装命令或编辑配置补救；更新检查或握手成功不等于实际版本已升级。

## 本人这几天的进展

本人问「我这几天的进展」这类按人、按时段的问题时这样拼。不要用 `world_get_context` 取事件，它按预算和每对象条数上限裁事件，取不全。

1. 时段照本人说的；没说就取最近三天（前天 00:00 到现在）。时区用本人说的，没说就用本机时区。回答开头写明时段和时区。
2. 用 world 插件的连接读。`world_get_connection` 的主体不是本人（例如旧 `/mcp` 的 Agent 身份）时换回插件连接，不拿 Agent 主体当本人。先用 `world_find_events` 分别以 `principal`、`on_behalf_of` 为本人主体，带 `occurred_from`、`occurred_to`，逐页取到 `next_cursor` 为空：这是本人记的，不论记在谁的对象上。再按「查询本人工作」找本人负责的 Mission 和 Task，逐个用 `world_get_object` 核对责任人，不凭标题推断；没核到的列为「未核对象」，不算作不属于本人。本人负责的对象各调 `world_get_events`，`since` 取时段起点（带时区），丢掉 `occurred_at` 晚于时段终点的，补上本人 Agent 和别人记在上面的；`records.latest_state` 是最新快照。读回被宿主截断或报超长时，改用 `world_find_events`（`subject` 为该对象，带 `occurred_from`、`occurred_to`，`limit` 调小）逐页取到 `next_cursor` 为空。
3. 认出三种记录。`content.text` 是 JSON 且 `format` 为 `world-source-evidence/0.1` 的是本机采集的事实，取其中的 `value`（是数组的逐项连成一句）、`quote` 和事件的 `occurred_at`；正文以 `【日进展】` 或 `【日进展·补充】` 开头的是日报，按条目拆开；快照看 `progress` 块各组件的 `attributes.entries`（`at`、`text`）和 `attributes.principal_name`。`state.refreshed` 是写快照，不单列；其余事件（生命周期、门、别的系统回流）照常列。
4. 同一 `event_id` 在几个对象上读到的算一条。说的是同一个结果（同一 PR、同一次换版、同一次实测）的只列一次。有采集事实就用它的时间、一句话和原话，日报、快照里的同一件只作旁证，注明哪份也记了；几条采集说同一件的合成一条，时间取最早的。只在日报里的照日报列，时间用日报写的时刻，没写就写日报那天并注明没有时刻；只在快照里、`at` 在时段内的按 `at` 列，注明来自快照、未经确认。拿不准是不是同一件的分开列。`corrected_by` 不为空的按更正后的内容列一次，`withdrawn_by` 不为空的不列。
5. 每条写事实时间（换算到本人时区）、一句话、来源和记录人显示名，按时间先后排。来源写「本机采集，原话“…”」（`quote` 为空就只写「本机采集」）、「日报 `event:<id>`」或「快照 `<ref>`」；`source.locator` 以 `local-capture:` 开头的只是本机定位符，不给本人看。
6. 记录人是本人、`on_behalf_of` 是本人，或记录人是 Agent（`principal_type` 为 `agent`）且显示名以「<本人显示名>的」或「<本人显示名> 的」开头（例如「<本人>的 Claude Code」；world 0.3 的 Agent 没有字段指回本人，只能这样认）的，算本人的。其余记录人（例如其他系统回流）的事件和快照里 `principal_name` 不是本人的条目，单列为「别人记在你对象上的」，写明记录人，不算本人做的。
7. 回答末尾写读了哪些对象、各取到几条事件、合并掉几条。未核对象、读失败或没取全的对象按对象列为缺口，一个对象只列一次，不说成没有进展；本人 Agent 记在别人对象上、又没带 `on_behalf_of` 的事件，这条读法取不到，也写明。没有缺口仍没有事件时，才说 world 里这段时间没有记录。
